# 0.5.7 gowest 原生编译与交付

## 当前状态

HTTP 默认、全部客户端配置、八阶段日志已经实现并经过自动化测试。原生入口覆盖 `init / plan / render / install / status / verify / urls / rollback / repair-fq / firewall`，定时任务和回滚保护在原生模式调用安装后的 `gowest`，不复制项目 `.py` 文件。

构建方案为 Nuitka：Python 逻辑转换为 C 后编译，独立运行时打入一个文件，不只是改后缀或 ZIP 装源码。不需要接收者安装 Python/PyYAML，但 Linux 安装仍需联网获取 APT 包和 sing-box。能避免直接看源码，不能保证无法逆向，也不隐藏必要的客户端配置、协议参数和用户自己的密钥。

当前宿主是 macOS arm64，没有可用的 Linux Docker 或虚拟机；不在生产代理服务器上安装编译器或编译。**Linux amd64/arm64 包尚未构建，不能宣称已可直接发给别人一键部署。** 目前 Mac 原生包用于参数准备、离线生成，不是 Mac 客户端自动安装器，也不是 Linux 服务器安装包。

当前 Mac 包名为 `dist/gowest-0.5.7-darwin-arm64-native.tar.gz`，包内程序与顶层目录均为 `gowest`。构建时执行离线 smoke test、原生模块编译审计和动态库依赖审计。0.5.6 已验证：沙盒禁读项目源码/pyenv 后生成配置通过；再禁止 Homebrew 后 `plan` 通过，但 `render` 因系统 LibreSSL 不支持 X25519 命令而失败，这是明确的外部 OpenSSL 3 CLI 依赖，不是 Python 或源码依赖。安装后的 Linux 依赖步骤会安装 Ubuntu OpenSSL；Mac 需自行准备。

包内仅五个白名单文件；`build-info.json` 记录项目名、版本和 11 个项目模块源码哈希。旧 0.5.6 原生包保留原名和内容，不能把它改名成新版本使用。

## 哪个可以发，哪个不能发

- `gowest-0.5.7-<平台>-<架构>-native.tar.gz`：原生交付包，仅二进制、简明说明、第三方许可、版本元数据和 SHA256SUMS。只发送所需平台的包。
- 不带 `-native` 的源码归档、本源码目录、`build_native.py`、`native/Dockerfile`、构建中间目录和编译报告：维护材料，含源码/构建细节，不给最终用户。历史 `go_to_west-*.tar.gz` 也是源码包。
- 任何 `settings.local.json`、生成目录、`secrets.json`、日志或已安装服务器的 `/etc/la-vpn`：包含私有配置，不随公共软件分发。

使用许可沿用项目拥有者决定；第三方组件的许可证独立保留。没有增加在线激活、授权码或远程控制机制。

## 独立 Linux 构建（维护者）

推荐用独立 Ubuntu 24.04 构建机/容器，2GB 以上内存。不要在现有代理服务器安装编译依赖。以下只定义构建方法，本次未在 Linux 实际执行：

```sh
docker buildx build --platform linux/amd64 -f native/Dockerfile \
  --output type=local,dest=dist/linux-amd64 .
docker buildx build --platform linux/arm64 -f native/Dockerfile \
  --output type=local,dest=dist/linux-arm64 .
```

需要已运行的 Docker 和相应架构构建器/模拟器，不由项目自动启动。构建上下文严格白名单，排除配置、私钥、旧归档和客户端脚本。Docker 构建下载固定版本 Python 构建依赖；Ubuntu 基础镜像标签及 APT 仓库仍会更新，因此不宣称逐字节可复现。

也可在有编译器的目标平台虚拟环境安装 `requirements-build.txt`，然后：

```sh
python3 -B build_native.py --work /tmp/一个尚不存在的本机构建目录 --jobs 2
```

构建器只接受新的工作目录和新的成品文件，拒绝覆盖已有发行包；成功前先做离线 smoke test。Mac 还审计动态库，拒绝残留的 Homebrew/pyenv 绝对路径依赖。原生包严格限制为五个文件，包含源码或符号链接会拒绝打包。`build-info.json` 记录实际平台、版本、各项目模块源码哈希和已执行/未执行的验证。

## 验收边界

离线验证包括：复制二进制到临时目录、清除 Python 环境变量、版本/帮助、HTTP 默认参数、1Gbps 转换、安装计划、全端配置生成、云防火墙模板生成/检查、定时任务帮助入口。Mac 的真实交互向导也需验证重新调用自身显示计划。

Linux 发布前还需要空白 Ubuntu 24.04 实装、服务重启/系统重启、回滚和外部 TCP/UDP 通路测试。原生 onefile 的父进程存在独立信号处理；已放宽子进程退出等待以免强杀回滚，但 Linux 断线行为未实测，原生版必须用 tmux。不要把源码版既有断线测试等同于原生版保证。

Mac 程序最低版本取决于编译器输出（此次为 macOS 13.2+ arm64），未签发 Developer ID/Apple 公证；不能在 Intel Mac、Windows 或 Linux 运行。Mac/Windows 原有自动检测安装客户端的 Shell/PowerShell 脚本仍属维护源码，不包含在无源码包里；不会将其简单藏进二进制然后声称已经原生化。
