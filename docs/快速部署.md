# gowest 新服务器快速部署（0.5.7）

适用：**空白 Ubuntu 24.04，amd64/arm64，至少 512 MiB 内存，公网 IPv4**。

这套脚本已经放在本地；现有 LA/DC 已通过独立的备份发布流程统一订阅，本机 Clash 也已同步。下面的安装命令只应在你将来准备的新服务器执行，不能拿来覆盖现有机器。

## 推荐：交互部署

下列是维护者源码版用法，不适合隐藏代码后分发。原生交付版用 `sudo ./gowest`；当前 Linux 成品尚未构建，需独立 Linux 构建环境，见 [原生编译与交付](原生编译与交付.md)。Mac 原生包不能上传到 Linux 使用。

把源码目录（或维护者源码包）上传到新服务器。建议先开一个 `tmux` 会话，SSH 断开后可用 `tmux attach` 回来看进度；进入目录：

```sh
tmux new -s gowest      # 可选但推荐
cd gowest
sudo bash deploy.sh
```

即使没用 `tmux`，0.5.3 起安装期间 SSH 断线也不会中断事务：安装继续进行，之后的输出写入 root 私有的 `/var/lib/la-vpn-deploy/session-output.log`。重新登录后用 `sudo bash /opt/la-vpn/deploy.sh status` 查看结果。

向导会依次询问：

1. 参数文件位置（默认 `settings.local.json`）。
2. 自动识别并显示公网 IP，回车使用；识别失败/结果冲突才要求人工填写。在 Mac 上准备参数仍需手填目标 IP。
3. 节点标签，例如 `LA`、`DC`，区分不同服务器；代理组名称保持统一。
4. 带宽只填一次，例如 `30Mbps` 或 `1Gbps`（也可只填 `30`，默认 Mbps）。同一值写入两个方向的 Hy2 目标；输入 `advanced` 才分别填写客户端上行/下行。
5. 共用份数或名字：一份直接回车；多份输入份数（如 `3`）或名字（如 `alice,bob:20Mbps,carol`，冒号后是该份上限）。每份一个订阅链接、独立凭据和独立端口（默认 TCP/UDP 20001 起，云安全组需放行）；带宽按链接分配，忙时均分，闲时可借满或到上限。
6. 每月流量上限：如 `1TB`、`512GB`，只写数字时按 GB（如 `800`），回车表示不设置；设置后再选超出时 `warn`（只提醒）还是 `stop`（暂停代理到下月）。
7. 默认 `2` HTTP，回车使用、再输入 `HTTP` 确认明文风险，无需域名证书。`1` HTTPS、`3` 或 `1,2` 为高级选择。电脑、Android、iOS 配置始终一次全部生成。
8. 可选的 Tailscale tailnet 域名。

随后展示计划和目标 IP，**输入 INSTALL 才开始安装**，无需再抄写 IP。留空取消。原有参数文件不会覆盖；如果存在，会询问是否只读复用。公网出口地址不一定等于 NAT 入站地址，仍需核对目标；探测失败不会猜测。

默认 HTTP 会生成 `http://新IP/sub/新令牌`。令牌不可猜测不等于传输加密，下载时凭据可能被链路上的第三方看到。HTTPS 模式需先准备可信证书和私钥，默认使用 8443；本版不自动申请或续期证书。

双选会同时开放默认 TCP 80 和 8443，HTTPS 为主入口，HTTP 使用同一域名和节点凭据，仍需明确确认明文风险。

带宽支持十进制换算：`1Gbps` → `1000 Mbps`，`1.5Gbps` → `1500 Mbps`；最终须为 1–100000 的整数 Mbps，不接受 `MB/s`、`GB/s` 等字节单位，避免混淆。配置中仍输出 Mihomo 能解析的整数格式。

相同默认值不代表线路上下行一定对称。云套餐的 30 Mbps 可能只限制服务器出站，1Gbps 也可能只是共享网口峰值；若实际网络较慢，应降低 Hy2 目标。脚本不测速、不修改云套餐，也不保证达到标称带宽。高级模式以客户端方向为准：上行是客户端上传，下行是客户端下载。已有参数文件只读复用，原来的上下行值不被改成相同值。

## 部署前云端准备

在云安全组放行：

- TCP 443：VLESS + REALITY。
- UDP 443：Hysteria2。
- TCP 80（HTTP 订阅）、TCP 8443（HTTPS 默认）；双选时两者都需放行。
- 保留你自己的 SSH 管理端口和云控制台救援入口。

不要开放全部端口。新机安装会检查本机 UFW，安全范围内新增 TCP/UDP 443 和所选订阅端口，并记录回滚信息；不改 SSH、不清空规则、不启停防火墙。已有重叠规则不会被接管；显式拒绝、自定义 nftables/iptables、检查失败会保留规则并提示人工核对。已有代理/网站或端口冲突仍拒绝安装。

云安全组在服务器之外：本版没有云 API 授权集成，不能凭 SSH 自动修改。安装前后明确提示“云安全组未验证”及所需端口，不能将 UDP 发送无报错或本地监听视为云端已开放。可以只读检查本机：`sudo bash deploy.sh firewall inspect --settings settings.local.json`。不希望自动新增本机规则时，使用 `install --host-firewall check`。

可直接选择工程内的 `firewall/Firewall-Rule-Template-json.json`（HTTP 80）或 `firewall/Firewall-Rule-Template-https-json.json`（HTTPS 8443）导入，二选一。它们保留 TCP 22 和 ICMP，不含不需要的 TCP 3389。SSH 暂时全网开放；更安全的做法是在准备参数后按自己的管理出口生成专用模板。详见 `firewall/README.md`，其中列出备份、导入追加/替换、默认拒绝、IPv6 和出站检查。

## 无交互参数准备（可选）

以下 `NEW_SERVER_IP` 必须换成你新机的实际公网 IPv4；数值带宽也按实际套餐/线路改，不要照搬。

```sh
bash deploy.sh init \
  --server-ip NEW_SERVER_IP \
  --node-prefix DC \
  --bandwidth 30Mbps \
  --accept-http-risk \
  --output settings.local.json

bash deploy.sh plan --settings settings.local.json

bash deploy.sh firewall generate --settings settings.local.json \
  --ssh-source YOUR_MANAGEMENT_IP/32 --output firewall.local.json
bash deploy.sh firewall check --settings settings.local.json --file firewall.local.json

# 将 YOUR_MANAGEMENT_IP 换成真实管理出口，导入并核对云规则后再安装。
sudo bash deploy.sh install \
  --settings settings.local.json \
  --confirm-new-server NEW_SERVER_IP
```

`init` 只写一个新的参数文件，不部署、不生成节点密钥；显式指定 `--server-ip` 时不联网，可在 Mac 准备后上传。在目标 Linux 上可省略 `--server-ip`，由脚本联网探测。实际安装独立生成密钥，不使用旧服务器密码。

不写 `--http/--https/--both` 就默认 HTTP；风险确认不能省略。旧参数文件只读复用，不会被自动改为 HTTP。

## 安装进度与日志

终端按 1–8 阶段显示：预检 → 回滚保护 → 系统依赖 → 内核下载校验 → 全端配置生成 → 网络和服务 → 本机验证与防火墙 → 保存结果。每阶段显示耗时；长步骤每 15 秒显示仍在运行，不显示虚构的完成百分比。

```sh
sudo tail -f /var/lib/la-vpn-deploy/install.log
sudo tail -n 60 /var/lib/la-vpn-deploy/command-errors.log
```

日志仅 root 可读；预检成功后创建持久日志，包含此前预检阶段。预检失败时不创建部署目录，原因只在终端显示。失败回滚会报告具体归档路径，日志随状态目录归档；不要继续看已经不存在的旧路径。命令超时或安装中断会先终止整个子进程组，避免子进程与回滚同时修改状态。

日志不主动打印订阅链接或完整命令参数，并对常见凭据模式脱敏；仍不建议公开原始日志。链接通过 `sudo bash /opt/la-vpn/deploy.sh urls` 单独查看；原生安装则用 `sudo /opt/la-vpn/gowest urls`。本机验证完成与云安全组、公网验收分开显示，不把“服务 active”当作全部成功。

套餐写 1Gbps 时，将 `--bandwidth 30Mbps` 换为 `--bandwidth 1Gbps`。已知不对称线路用 `--up 10Mbps --down 30Mbps` 替代；原 `--up 10 --down 30` 仍支持，不能与 `--bandwidth` 同时填写。

双入口参数示例（在目标 Linux 运行，域名及证书路径需替换）：

```sh
bash deploy.sh init --bandwidth 30Mbps --both --accept-http-risk \
  --subscription-host sub.example.com \
  --certificate /root/fullchain.pem --private-key /root/privkey.pem \
  --output settings.local.json
```

再运行 `firewall generate` 会自动包含两种订阅端口，无需手工拼接两份静态模板。

上面是示意参数，不是任何 30 Mbps 线路都适用的测速结论。若暂时无法限定 SSH 来源，用 `--allow-world-ssh` 替代 `--ssh-source ...`，后续再安全收窄；不要把文档中的占位地址直接导入。

## 安装完成后

项目名已改为 gowest；服务器内部 `/opt/la-vpn` 和服务标识为兼容旧版继续保留，以下路径不是漏改。

```sh
sudo bash /opt/la-vpn/deploy.sh status
sudo bash /opt/la-vpn/deploy.sh verify
sudo bash /opt/la-vpn/deploy.sh urls
sudo bash /opt/la-vpn/deploy.sh urls --transport all
```

最后一条显示普通/严格 YAML 及额外的小火箭入口。旧两条 URL 保存在 `/var/lib/la-vpn-deploy/generated/subscription-urls.txt`，原生节点及 `.conf` 地址保存在同目录 `client-urls.txt`，仅 root 可读。小火箭先添加 `-nodes` 节点订阅，再在“配置”页启用对应 `.conf`；详见 [小火箭使用指南](小火箭使用指南.md)。

按客户端查看导入说明（均含私密链接，不要公开）：

```sh
sudo bash /opt/la-vpn/deploy.sh urls --client mac        # Clash Verge Rev，含 clash:// 一键导入链接
sudo bash /opt/la-vpn/deploy.sh urls --client windows    # 同上
sudo bash /opt/la-vpn/deploy.sh urls --client android    # Clash Meta for Android，含 clashmeta:// 链接
sudo bash /opt/la-vpn/deploy.sh urls --client shadowrocket
```

Mac / Windows 也可以直接运行本项目 `clients/` 里的一键脚本，按提示粘贴日常订阅地址，脚本会检测环境、安装 Clash Verge Rev 并导入，详见 `clients/README.md`。Windows 不要用 Clash for Windows，它的内核不支持本项目的节点。

小火箭用户可直接运行 `sudo bash /opt/la-vpn/deploy.sh urls --client shadowrocket`，按服务器自动生成的说明复制三条完整链接，不必拼接。说明另存为同目录 `shadowrocket-import.txt`（私有、不公开发布）。日常和全公网配置都选“全局路由 → 配置”，首页选同机 Hy2；详细区别见 [小火箭使用指南](小火箭使用指南.md)。旧机不能靠重新安装获得此命令。

在 Clash Verge **新增订阅**导入其中一条；暂时保留旧订阅供比较，不复制旧订阅的增强 JS。新配置已有完整的自动组、DNS/TUN 修正规则。保持规则模式、`出口选择 → 自动回退`；需要接管 WebRTC/不遵循系统代理的应用时，在 Clash 界面启用 TUN。按场景使用见 [桌面使用指南](桌面使用指南.md)。

注意：订阅导入与 TUN 开关仍要在客户端操作；安装器不会遥控本机或 mini。严格版也不是系统级 kill switch。

## 新机验收建议

先确认 TCP/UDP 443 对外可达、订阅能下载，再对比两个协议的实际访问、TUN 下 HTTP/STUN 出口和小文件测速。服务端 `verify` 只验证本机服务与订阅内容，不证明跨境线路性能、浏览器无泄漏或 Claude 账号状态。

客户端可运行连续小流量下载测试（将 IP 占位替换为新机地址，三轮共请求 24 MiB，不含协议开销）：

```sh
python3 -B probe.py --expect-exit-ip NEW_SERVER_IP --download-mib 8 --rounds 3 --interval 5
```

不自动重启或改选节点；只统计完整成功样本，失败另列。直播还需实际推流检验持续上传、丢帧及断流，不能用下载峰值替代。

如果安装失败，脚本会尝试恢复网络参数并归档本工具文件。错误命令的 stderr 保存在 root 私有的 `command-errors.log`；发生回滚后，它随状态目录进入 `/var/lib/la-vpn-archives/rollback-*`。日志可能包含配置路径或敏感诊断，分享前先脱敏。

需要手动回滚本工具时：

```sh
sudo bash /opt/la-vpn/deploy.sh rollback
```

回滚保留可恢复归档，不会自动卸载 APT 依赖、删除系统账号或清空 vnStat 数据。回滚后再次安装会被新机保护拒绝，需要先核对残留；不能直接强制覆盖。

0.2.0 修补版已在一台新 Ubuntu 24.04 amd64 服务器完成实装、公网订阅及双协议 HTTP/UDP 验证。0.3.1 起的 FQ 改动通过离线/模拟测试及隔离网络命名空间真实 tc 验证。其他服务器的线路、带宽、云安全组和重启恢复仍需分别验收。详细边界见 [CHANGELOG](../CHANGELOG.md#验证现状)。
