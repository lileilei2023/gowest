# gowest 详细说明（维护者手册）

双协议代理部署与配置生成项目，支持四类客户端：Mac / Windows 的 Clash Verge Rev、Android 的 Clash Meta for Android（均为 mihomo 内核）和 iOS 的 Shadowrocket。

版本：0.5.7，2026-10-27。项目展示名、源码目录、命令与新包名前缀统一为 **gowest**。

为兼容已部署服务，服务器内部的 `/opt/la-vpn`、`/etc/la-vpn`、`/var/lib/la-vpn-deploy` 和 `la-vpn*` systemd 标识继续保留。各版本变化见 [CHANGELOG](../CHANGELOG.md)。

代理组统一为「出口选择 / 自动回退 / AI / Claude / YouTube / TikTok」，节点按 LA、DC 等标签区分；桌面场景见 [桌面使用指南](桌面使用指南.md)，手机见 [小火箭使用指南](小火箭使用指南.md)，原生编译见 [原生编译与交付](原生编译与交付.md)。

**这是通用复建源码，不是生产配置备份，不包含现有节点密钥。安装器只允许全新服务器；现有 LA/DC 的定向订阅升级须使用单独审核、带备份的事务，不运行全量 install。**

适用范围：空白 Ubuntu 24.04、amd64/arm64、systemd、至少 512 MiB 内存、有公网 IPv4。其他系统、已有代理/网站的机器、原地升级或接管旧服务不在本版范围内。没有 `--force` 覆盖选项。

**维护者源码入口：**在新服务器源码目录运行 `sudo bash deploy.sh`，公网 IP 自动探测，填写一次带宽，默认 HTTP、确认风险，核对目标后输入 `INSTALL`。完整步骤见 [快速部署](快速部署.md)。在 Mac 上只准备参数，需明确填写目标 IP，不安装服务；`bash deploy.sh --version` 可查看版本。给他人交付时应使用对应平台的 `gowest-*-native.tar.gz`，不要发送整个项目目录。

## 已实现

- 固定版本和 SHA-256 校验的 sing-box 安装（当前锁定 1.14.3）。
- VLESS + REALITY + Vision（TCP 443）与 Hysteria2 + salamander（UDP 443），同服务器直接出站。
- 每次新部署生成独立 UUID、X25519 密钥、Hy2/混淆密码、自签证书、证书指纹和随机订阅令牌。
- 参数化生成两份常规 YAML，含 `出口选择 / 自动回退 / AI / Claude / YouTube / TikTok`；另生成原生 Hysteria2/VLESS 节点订阅和两份小火箭 `.conf`。
- 按环境选择 BBR；默认/最大 socket 缓冲至少 4 MiB/32 MiB，保留更大的原值；TCP MTU 探测；安全范围内应用 FQ。
- 代理服务失败后 3 秒重启；独立 Nginx 订阅服务；vnStat 流量展示定时更新。
- 冲突检测、30 分钟安装保护定时器、失败回滚、改动指纹检查和可恢复归档。
- 离线配置检查、隔离协议测试与可选的客户端 HTTP/STUN/小流量测速工具。
- 四端客户端导入：服务器 `urls --client` 输出 Clash Verge Rev（`clash://`）、CMFA（`clashmeta://`）一键导入链接和小火箭完整说明；`clients/` 提供 Mac / Windows 环境检测与一键安装导入脚本（固定版本 + SHA-256）。
- HTTP/HTTPS 两份云防火墙模板；可按自定义订阅端口、SSH 来源生成新模板并离线校验，不自动应用规则。
- 新机安装自动检查并保守新增 UFW 所需端口（不启停防火墙、不清空规则、不动 SSH），未知/复杂规则提示人工核对；`firewall inspect` 只读检查。云端模板不会自动导入。

自动组是**故障回退，不是自动选最低延迟**。两种协议仍共用一台服务器，不能防整机宕机。BBR 主要影响 TCP；Hy2 使用自身的 QUIC 拥塞控制。

## 1. 先准备参数，不操作现有机器

选一份示例复制为 `settings.local.json`：

- 默认方式：`settings.http.example.json`，HTTP 80，**下载过程会明文传输订阅凭据**。其中显式的 `allow_insecure_http: true` 是风险确认，不是加密保护。
- 可选加密方式：`settings.example.json`，HTTPS 订阅，需准备对应域名的可信证书和私钥。

必须修改：

| 参数 | 说明 |
| --- | --- |
| `server_ip` | 向导在目标 Linux 上自动探测；手写参数或在 Mac 准备时须填写。示例的 `192.0.2.10` 不能用于真实安装 |
| `node_prefix` | 每台服务器的节点标签，例如 `LA`、`DC`；向导及 `init --node-prefix` 均可设置。只影响节点，不影响代理组名称；默认 `LA` 保持参数兼容 |
| `hy2_up_mbps` / `hy2_down_mbps` | 内部仍保存两个整数 Mbps；向导/`init --bandwidth` 填一次，自动写入两项。不对称线路用高级方式分别填写 |
| `subscription.host` | 新 IP 或你的订阅域名；域名需要你预先正确解析 |
| `subscription.port` | HTTP 可用 80；HTTPS 示例用 8443，避免与 REALITY 的 TCP 443 冲突 |
| `subscription.http_port` | 可选：HTTPS 主入口同时提供 HTTP，通常为 80；必须同时设置 `allow_insecure_http: true` |
| `tailnet` | 可选，填自己的具体 `xxx.ts.net`；没有就留空 |
| `hosts` | 可选，自己的静态域名/IP 映射；默认不会复制旧 Mac 的设备地址 |

`ipv6: true` 保留 IPv6 能力；这不证明所有平台都已拦截 IPv6，仍须结合 TUN 和实际网络验收。`traffic.total_bytes` 是整台服务器的每月流量上限，0 表示不设置（不会擅自填“1 TiB”）；`metering` 为 `both`（进+出，默认）或 `outbound`（只计出方向）；`on_exceed` 为 `warn`（默认）或 `stop`。`users` 为空表示一份（端口 443）；填写 2 个以上名字即启用 `fair_share`：每个名字一个订阅链接和独立端口（`user_port_base` 默认 20000，即 20001 起，须低于 32768 的临时端口范围），Hy2 改用 BBR，出口建立 HTB 队列，每个链接保底 `总速率/N`、可借用到总速率或 `user_caps` 中该链接的上限（总速率为带宽的 95%）。所需内核模块缺失时，安装器会安装 `linux-modules-extra-$(uname -r)`，必要时添加 Ubuntu 官方源 `/etc/apt/sources.list.d/gowest-ubuntu-kernel.sources`（回滚时归档）。

带宽无需通常分两次填写：`--bandwidth 30Mbps` 或 `--bandwidth 1Gbps` 即可。若已知不对称，用 `--up 10Mbps --down 30Mbps` 替代（不能混用）。方向以客户端为准：上行是客户端上传，下行是客户端下载。云套餐的标称带宽可能只指服务器出站，1Gbps 也可能仅是共享网口峰值；这些值只是 Hy2 配置目标，不是对称线路或满速保证，不改云套餐，不执行测速。

查看计划，不联网、不安装：

```sh
python3 -B vpn.py plan --settings settings.local.json
```

只生成一套新配置，供离线审阅（需要 Python 3.10+、OpenSSL、PyYAML；本地可在虚拟环境中安装 `requirements.txt`，Ubuntu 安装器会安装 `python3-yaml`）：

```sh
python3 -B render.py --settings settings.local.json --output generated-review
python3 -B check.py --generated generated-review
```

输出目录必须尚不存在。它为 0700，密码、密钥、订阅为 0600；不会覆盖既有生成结果，也不操作 Clash。`install` 会在新服务器重新生成自己的独立密钥，**不会采用这套离线预览密钥**。

## 2. 在新服务器部署

先在云安全组确认允许：SSH 管理端口、TCP 443、UDP 443，以及所选订阅 TCP 端口（双选则含 80 和 8443）。不要开放全部端口。安装器可以保守新增本机 UFW 规则；显式拒绝、已有重叠规则、自定义 nftables/iptables 或状态不明时保持原规则并提示。可用 `install --host-firewall check` 禁止所有防火墙变更。没有云 API 授权时无法检查或修改云安全组，始终提示未验证；本机监听不代表公网可达。

现成可导入模板和命令见 `firewall/README.md`：HTTP 使用 `firewall/Firewall-Rule-Template-json.json`；HTTPS 默认 8443 使用另一份模板。不开放 RDP 3389。静态模板暂允许全网 SSH，生成器则要求明确管理来源或显式接受全网开放。导入前备份原规则，确认追加/替换行为、未匹配入站的默认拒绝和出站允许策略；本地检查不代表云端已生效。

通过 SSH/SCP 将本目录和 `settings.local.json` 传到**新服务器**，确认登录目标之后运行：

```sh
sudo python3 -B vpn.py plan --settings settings.local.json
sudo python3 -B vpn.py install --settings settings.local.json --confirm-new-server 新服务器公网IP
```

必须将中文占位替换为与配置相同的真实 IPv4。原服务器已有 sing-box 配置，脚本会拒绝安装；本次复建没有在原服务器执行这些命令。

安装器会：

1. 检查系统、已占用端口和既有服务，拒绝覆盖。
2. 保存事务状态并启动保护定时器；安装 Ubuntu 依赖，校验并解包官方 sing-box 二进制。
3. 新建受限服务账号、独立密钥和配置。
4. 快照系统网络参数，应用可支持的优化。
5. 启动独立服务，验证配置、TCP/UDP 监听和所有已启用传输方式的订阅下载内容。
6. 检查本机防火墙并安全新增 UFW 规则；本机/云端未完成项显示警告。提交本机安装状态、解除安装保护、保存订阅地址；不声称公网验收完成。

订阅地址保存在新服务器的：

`/var/lib/la-vpn-deploy/generated/subscription-urls.txt`

文件为 root 私有。用 SSH 查看或安全复制给客户端；不要将带令牌的地址贴到公开日志、代码仓库或在线订阅转换网站。

正常格式为：

```text
https://你的订阅域名:8443/sub/<新令牌>
https://你的订阅域名:8443/sub/<新令牌>-us
```

HTTP 兼容模式则是 `http://新IP/sub/<新令牌>`。新机不会自动继承旧服务器的 IP 或原订阅 URL。

双选时默认输出 HTTPS 主入口；用 `sudo bash /opt/la-vpn/deploy.sh urls --transport all` 查看两种入口，或添加 `--transport http|https --client android|shadowrocket|mac|windows`。两者共用同一套节点凭据：只要 HTTP 开着，凭据就仍可能通过明文泄露，不能把“双选”视为比 HTTPS 更安全。

## 3. 客户端如何使用

| 平台 | 客户端 | 订阅 | 导入方式 |
| --- | --- | --- | --- |
| macOS | Clash Verge Rev 2.5.8 | 日常 `…/sub/<令牌>`、全公网 `…-us` | `clients/macos/gowest-client.command` 一键脚本，或 `urls --client mac` 的 `clash://` 链接 |
| Windows | Clash Verge Rev 2.5.8 | 同上 | `clients/windows/gowest-client.cmd` 一键脚本，或 `urls --client windows` 的链接 |
| Android | Clash Meta for Android | 同上 | 手机浏览器打开 `urls --client android` 的 `clashmeta://` 链接 |
| iOS | Shadowrocket | `-nodes` + `-shadowrocket.conf` / `-us-shadowrocket.conf` | `urls --client shadowrocket` 的分步说明 |

三个 mihomo 客户端使用同一份 YAML：Tailscale 的 macOS、Windows（`.exe`）、Android（包名）进程直连例外都已写入。**Clash for Windows / 旧版 Clash for Android 的内核不支持 VLESS+REALITY 和 Hysteria2，不能使用。** 一键脚本只检测环境、安装和导入订阅，不改系统代理、DNS 或 TUN，详见 `clients/README.md`。

以下以 Clash Verge Rev 为例。在本机或 mini **新增一条订阅**，不要覆盖旧订阅，也不要把旧订阅绑定的增强 JS 一起复制过来。新 YAML 已包含完整规则，不依赖当前 Mac 的脚本 UID、控制端口或控制密钥。

- 普通版：国内直连；AI / Claude / YouTube / TikTok 优先分流；其他流量经 `出口选择`。保留手动 DIRECT。
- 严格版：无国内直连规则，且 `出口选择` 不提供手动 DIRECT；仍保留 Tailscale、私网等明确直连例外。
- 两版都默认 `出口选择 / AI / YouTube / TikTok → 自动回退`，`Claude → AI`。自动回退优先同机 Hy2，故障切同机 VLESS，不跨 LA/DC；也可手动固定节点。保存过的旧选择可能覆盖初始值，需要检查一次。
- 要接管 WebRTC 等不遵循系统代理的流量，在 Clash Verge 中开启 TUN，并授予所需权限。本工具不会远程操作你的应用开关。
- 生成配置的 `tun.enable` 默认 false，避免导入时擅自接管网络；Clash Verge 的应用级设置还可能覆盖此字段。

已生成的 TUN/DNS 规则包括：服务器 IPv4 `/32` 路由排除、Tailscale IPv4/IPv6 排除、UDP/TCP 53 劫持、国内域名 fake-IP 例外、各场景域名经对应策略的代理 DoH、可选的具体 tailnet DNS 策略。Clash Verge 的应用级 TUN 设置仍可能覆盖订阅字段。

严格版更严格不等于全局 kill switch。关闭 TUN、应用绕过接管、私网/进程例外、浏览器独立 DoH、IPv6 或应用合并配置，都需要按实际情况检查。普通版的国内直连也可能涵盖某些 STUN 服务。不能承诺零泄漏、住宅 IP 或 Claude 不触发风控。

## 4. 独立的 Mac DNS 修复边界

历史上的 `198.18.0.2` 系统 DNS 残留不是云服务器配置问题；服务器安装器不能替每台 Mac 修复系统 DNS。应先确认系统正常直连 DNS，再在 Clash 界面测试 TUN 开/关后的恢复。

如果关闭 TUN 后只有 tailnet 域名不能解析，可在核对后安装 macOS scoped resolver：文件名为 `/etc/resolver/你的tailnet.ts.net`，内容为 `nameserver 100.100.100.100`。生成器在设置了 tailnet 时提供 `tailnet-resolver.conf` 阅读用文件，但**不会自动写 `/etc/resolver` 或打开 Tailscale 全局 DNS**。这里涉及管理员权限、已有文件冲突，应单独确认。

## 5. 验证与回滚

新服务器状态及本地验收：

```sh
sudo python3 -B /opt/la-vpn/vpn.py status
sudo python3 -B /opt/la-vpn/vpn.py verify
```

本地验收不代表中国到新机的 UDP 通路、云安全组、实际公网带宽或 Claude 账号已通过验证。切换新订阅后，在客户端可手动运行：

```sh
python3 -B probe.py --proxy http://127.0.0.1:7897
python3 -B probe.py --proxy http://127.0.0.1:7897 --stun --download-mib 4
python3 -B probe.py --proxy http://127.0.0.1:7897 --expect-exit-ip NEW_SERVER_IP \
  --download-mib 8 --rounds 3 --interval 5
python3 -B probe.py --proxy http://127.0.0.1:7897 --expect-exit-ip NEW_SERVER_IP \
  --download-mib 8 --upload-mib 4 --rounds 3 --target-mbps 30
python3 -B probe.py --proxy http://127.0.0.1:7897 --expect-exit-ip NEW_SERVER_IP \
  --download-mib 8 --parallel 2 --rounds 3 --target-mbps 30
```

第二条会对两家公共 STUN 服务发送 UDP，并经当前所选代理请求 4 MiB 测试数据。第三条需替换 `NEW_SERVER_IP`，先核对 HTTP 出口，再在同一运行中的代理上连续请求三次 8 MiB，名义下载数据预算共 24 MiB（不含协议开销）。每轮须 curl 成功、HTTP 200 且下载字节完整才计入最小/中位/最大速度；失败会显示并返回非零退出码，不把 403 或超时的残缺数据当成测速通过。

第四条名义载荷 36 MiB，测 8 MiB 单连接下载与 4 MiB 上传各三次；第五条 48 MiB，测两条同时下载的总吞吐。总预算上限 256 MiB，不包含协议开销/重传，不是云账单流量硬上限。公共测速端点本轮对两台机器的 16 MiB 请求都返回 403，所以单次请求仍限定为已验证的 1–8 MiB；403 不计作网络速度。每次传输 30 秒超时，无自动重试；参数错误/预算超限会在联网前拒绝。并发总速率使用总字节除以共同墙钟时间，不相加各连接平均速度。

`download_mbps` 含建连/首包时间，`body_phase_mbps_estimate` 排除首包等待，仅为传输阶段估计；二者都不证明长期稳定满速。`--target-mbps 30` 只计算有效载荷的参考利用率，不会设置/提高 Hy2 带宽。上传使用 HTTP POST；经 Hy2 时底层客户端—服务器传输为 QUIC/UDP，但不是原始 UDP 发包容量测试。直播还需单独做持续上行、抖动、丢帧验收。

脚本不会选择节点、重启内核、开关 TUN 或自动更改带宽参数；应用自身的故障回退仍可能发生，所以相同 IP 不证明协议相同。**TUN 关闭时 STUN 可能得到直连公网 IP**；这是操作系统 UDP，不是经 HTTP 代理的 UDP 测试。工具不代替浏览器 WebRTC/IPv6 完整测试，也不代表持续上传/直播验收。

回滚本工具部署：

```sh
sudo python3 -B /opt/la-vpn/vpn.py rollback
```

回滚前核对文件摘要、网络参数和已变更队列；发现外部改动则停止，避免覆盖后来修改。正常回滚停止本工具服务、恢复记录的网络参数，并将文件和密钥移动到 `/var/lib/la-vpn-archives/rollback-*`，可恢复，不删除历史凭据。

回滚不是系统镜像恢复：APT 依赖、已下载的软件、vnStat 数据、加载过的内核模块及专用系统账号会保留；不会自动清理这些可能被其他功能使用的对象。账号保留意味着回滚后再次安装会被新机保护拒绝，需人工检查，而不是直接重跑覆盖。

保护定时器用于未提交的安装，成功提交后不会被迟到的定时器撤回。它不是服务器断网后的长期自动恢复服务；安装期间断电/重启、磁盘故障或冲突改动仍可能需要人工处理。运行命令超时与失败均会尝试回滚，不能承诺所有故障都能自动恢复。

## 6. 优化策略与有意未实现的内容

- 保留 BBR/FQ/缓冲/服务重启的历史优化；不修改物理网卡 MTU，不刷第三方内核，不关闭 IPv6 或全局防火墙。
- FQ 只替换识别为默认参数的 `pfifo_fast`。遇到 `mq`、`fq_codel`、HTB、CAKE 等未知或自定义队列会保留，不摧毁限速/多队列设置。已有 FQ 也不重置其参数。开机时重新检查条件。
- 非零句柄 FIFO 不再一概认定不可优化：自动接受匹配本工具本次开机回滚凭据的队列；旧版无凭据的队列须显式审查后 `repair-fq --confirm-server IP --adopt-default-fifo`。仅限单一 root、默认选项、无其他队列/类/根过滤器、且与部署快照匹配；绝不扩大为任意非零句柄可替换。
- `status` 显示实际 root/handle、BBR、FQ 生效情况和跳过原因；`verify` 遇到受管 FQ 丢失/选项改变会失败。仅 `default_qdisc=fq` 或 FQ oneshot 服务 active 不算验收。修复只操作 FQ，不改订阅，不重启代理；现有旧安装须先安全升级脚本与文件摘要，不能覆盖解压后直接重跑 install。
- 带宽显式参数化，不从云套餐名推断，不默认做大流量测速，不保证跑满套餐。若套餐是 30 Mbps，理论上限约 3.75 MB/s，所有连接共享。
- 没有香港中转、WARP、住宅代理、第三台备用机或后台用户管理；这些都不是当前已验证架构的一部分。
- 流量展示是网卡整机月流量，不是精确分用户计费：代理的每个字节都会进出服务器各一次，所以显示值约为客户端实际用量的两倍，这也是云套餐通常计量的口径；只计出方向的套餐可设 `metering: outbound`。`on_exceed: warn` 只显示用量；`stop` 会在达到上限时暂停代理服务，到下个月或调高上限后由统计定时器自动恢复，管理员自己手动停止的服务不会被它启动。到期日只用于显示。
- HTTPS 支持你提供的可信证书，但**本版不自动申请/续期证书**。REALITY 占 TCP 443，因此 HTTPS 订阅默认使用 8443。证书续期和域名迁移需另行规划；修改受管证书后，回滚的摘要保护会要求人工核对。
- 没有部署后自动升级；升级 sing-box 需更新版本和两种架构的官方 SHA-256，并重新验证兼容性。
- Mihomo 的 GEOSITE/GEOIP 规则需要正常的规则数据库。标准 Clash Verge 环境通常会管理它们；全新裸 Mihomo 环境需预先提供，离线验证不应依赖临时在线下载。

## 按链接管理（0.7.0）

- `users list / add / remove / reset / set`，修改类命令需要 `--confirm-server <IP>`（`remote.sh` 自动带上）。只有多人安装可用；一个人用的安装端口是 443，不能事后加人。
- **端口固定**：第一次增删时，把每个人当前的端口写入 `user_ports`。之后删人不会挪动别人的端口；新加的人用基准端口以上最小的空闲端口。
- **流量计数**：`la-vpn-subinfo.timer` 每 5 分钟运行一次，读取 `inet la_vpn_acct` 表里每个端口的计数器（进入 = 客户端上传，发出 = 客户端下载），累计到 `/var/lib/la-vpn-deploy/user-traffic.json`。计数器比上次读数小，说明表被重建过（例如重启），这时按新读数累加，已统计的用量不丢。自然月切换时清零。
- **暂停**：链接的本月用量达到 `user_quota`，或已过 `user_expire` 那一天，就在该端口的计数规则前加一条丢弃规则，不重启服务。条件解除后（新的月份、调高额度、延后或取消到期日），下次统计时自动去掉。整台服务器的 `traffic.on_exceed=stop` 仍然暂停整个代理服务。
- **订阅头**：设了额度的链接显示自己的用量和额度；没设额度的链接显示整台服务器的用量和上限。链接自己的到期日优先于整台服务器的到期日。
- **这张表的边界**：只在自己的 `inet la_vpn_acct` 表里计数和丢弃，链的默认策略是放行，不改动 UFW 或管理员的规则。回滚时删除整张表。


## 稳定性：端口跳跃与备用协议（0.9.0）

- **端口布局**：每个订阅链接有三组端口，都由它固定的主端口推算，所以增删别人时不会变。
  - 主端口：VLESS REALITY（TCP）和 Hysteria2（UDP）。一个人用时是 443，多人时从 20001 起。
  - 第二端口：AnyTLS（TCP）和 TUIC（UDP）。一个人用时是 2443，多人时是主端口加 1000。
  - 跳跃端口：64 个连续的 UDP 端口，从 24576 起每人一组，按 64 对齐。
- **端口跳跃的实现**：`la-vpn-hop.service` 在代理启动前加载 `/etc/la-vpn/hop.nft`，在 gowest 自己的 `inet la_vpn_hop` 表里把每组跳跃端口 `redirect` 到这个人的 Hy2 端口。客户端（mihomo）的 `ports` 设为这一组，每 30 秒换一次端口。
- **跳跃流量照样计数、照样均分**：转发发生在 prerouting，早于计数规则所在的 input，所以计数时看到的已经是主端口。回包离开时，内核会把源端口恢复成跳跃端口，所以带宽分配队列要用一条 u32 掩码规则匹配整组 64 个端口。这也是跳跃端口必须按 64 对齐的原因。
- **自动回退顺序**：Hy2 → VLESS → TUIC → AnyTLS，每 60 秒做一次健康检查，连续失败 2 次就切换。这些组里没有 DIRECT。
- **证书固定**：TUIC 和 AnyTLS 使用和 Hy2 相同的自签证书，客户端固定证书的 SHA-256 指纹，所以 `skip-cert-verify` 只是跳过 CA 校验，证书被替换时仍然拒绝连接。小火箭的链接格式无法固定 TUIC 和 AnyTLS 的证书，所以小火箭只使用 Hy2 和 VLESS。
- **开关**：`options --hopping on|off --protocols tuic,anytls|none --obfs on|off`，网页里是"线路与协议"卡片。修改会走和升级相同的流程：先核对文件指纹，失败自动恢复。客户端更新订阅后才会生效，更新之前旧节点照常可用。关闭 Hy2 混淆是例外：服务端和客户端必须一致，所以在客户端更新订阅之前，Hy2 会连不上，此时会自动回退到其他协议。
- **线路体检**：`linecheck` 在你自己的电脑上运行，不经过任何代理。
  - 路由：用 traceroute 根据骨干网的特征 IP 段识别线路，比如 59.43 是 CN2，202.97 是 163，218.105 是 9929，219.158 是 4837，223.120 是 CMI。
  - 延迟和丢包：做 20 次 TCP 握手统计。
  - 速度：下载一次服务器上 16 MiB 的测速文件。测速地址和订阅地址共用同一个私密令牌。
